## Подпись и нотарификация SSH Hub

Новые сборки используют **Developer ID Application: Anton Akinin (T3V8ZUE97C)**, выданный Apple. Команда издателя — `T3V8ZUE97C`. Приложение и все встроенные помощники подписываются с Hardened Runtime и защищённой меткой времени. Приватный ключ находится в связке «Вход» Mac сборки и не входит в репозиторий или приложение.

### Для пользователей

В нотарифицированной сборке не нужно устанавливать сертификаты или настраивать доверие вручную. В «Настройки → Обновления» отображается проверенный статус Apple Developer ID. Установщик самоподписанного сертификата и предложение при первом запуске удалены.

При первом переходе со старой локальной подписи macOS может один раз запросить разрешение доступа к ранее сохранённым паролям: издатель изменился. Последующие сборки используют стабильный Developer ID той же команды; имена сервисов, bundle ID и пользовательские данные сохраняются. Приложение не переписывает ACL пользовательских паролей. Старый сертификат в пользовательской связке автоматически не удаляется.

### Для сборки

- `DeveloperIDApplication.cer` — только публичный сертификат Apple.
- `signing-identity.sha1` — публичный SHA-1 identity, используемой сборщиком.
- `developer-team-id.txt` — закреплённая команда Apple Developer.
- `SSHHub.provisionprofile` — публичный профиль Developer ID для macOS и этого bundle ID; входит в приложение как `Contents/embedded.provisionprofile`. Приватных ключей в профиле нет.
- `SSHHub.entitlements` — только идентификатор приложения, команда и его собственная группа Keychain `T3V8ZUE97C.com.olshaniki.ssh-aliases`. Помощники этих прав не получают.

Скрипт проверяет, что identity — действующая Developer ID Application нужной команды. Подписывает помощники раньше основного приложения, без `--deep` при подписании и без ослабляющих entitlements. Проверка выполняется с `--deep --strict` и требованием Apple Developer ID команды издателя. Одного совпадения bundle ID недостаточно. Нормальное продление сертификата той же команды не требует изменения политики обновления.

Touch ID хранит только ключ разблокировки базы в Data Protection Keychain с `biometryCurrentSet`, `WhenUnlockedThisDeviceOnly` и отключённой синхронизацией. Для этого macOS требует авторизованные профилем права приложения. Скрипты проверяют команду, срок профиля, macOS, Developer ID certificate и разрешение собственной группы; в обеих архитектурах подписанное приложение должно иметь ровно минимальные entitlements. Профиль обновляют при истечении срока или продлении сертификата, без смены bundle ID и группы. Доступ к старым паролям и ACL не расширяется. См. [требования Apple к Keychain на Mac](https://developer.apple.com/documentation/technotes/tn3137-on-mac-keychains).

```sh
zsh Scripts/sign-app.sh --check
zsh Scripts/build.sh /private/tmp/ssh-hub-build
zsh Scripts/sign-app.sh --verify '/private/tmp/ssh-hub-build/SSH Hub.app'
python3 Tests/SigningContinuityTests.py
```

Проверка непрерывности использует только два временных приложения и отдельную связку с синтетическим паролем; реальные пароли не читаются. Ad-hoc остаётся явной возможностью только для локальной разработки через `SSH_HUB_SIGN_IDENTITY=-`, без автоматического fallback и без публикации таких сборок.

### Доступ к сервису нотарификации

Создай пароль приложения в Аккаунте Apple самостоятельно и введи его в скрытом запросе `notarytool`. Пароль не передаётся в аргументах, исходниках, переменных окружения или чате:

```sh
xcrun notarytool store-credentials 'SSHHub-DeveloperID-Notary' --apple-id '<Apple Account>' --team-id T3V8ZUE97C
```

Профиль хранится в Связке ключей. Скрипт использует только имя профиля; альтернативное имя можно задать через `SSH_HUB_NOTARY_PROFILE`.

### Нотарификация

```sh
zsh Scripts/notarize.sh /private/tmp/ssh-hub-build /private/tmp/ssh-hub-dist
```

Сначала скрипт отправляет Apple ZIP подписанного приложения и требует статус `Accepted`, затем прикрепляет и проверяет билет приложения. После этого создаёт подписанный DMG, отправляет его на нотарификацию и прикрепляет отдельный билет образа. Итоговые ZIP и DMG содержат приложение с билетом для офлайн-проверки. Для приложения и DMG выполняются проверки Gatekeeper. `SHA256SUMS` создаётся после последнего изменения артефактов.

Если ожидание истекло, Apple продолжает обработку. Не публикуй кандидата как проверенный: прочитай JSON с идентификатором заявки, затем получи статус и журнал через `notarytool info` и `notarytool log`. Повторная отправка того же файла автоматически не нужна.
