## Постоянная подпись SSH Hub

Сборки подписываются сертификатом `SSH Hub Local Code Signing`, действующим до 21 октября 2036 года. `SSHHub-CodeSigning.cer` содержит только открытый сертификат; приватного ключа в репозитории нет. Отпечаток SHA-256:

```text
4E404F8EAED616350E2E759C11296408B0F863712CE11AFA5A59F91511C2D684
```

Одинаковые bundle ID, сертификат и designated requirement позволяют Связке ключей узнавать приложение после пересборки. При переходе с прежних ad-hoc сборок может потребоваться заново разрешить доступ к каждому сохранённому объекту кнопкой «Разрешать всегда». Блокировка Связки ключей и отдельные проверки Touch ID сохраняются; существующие ACL и пароли приложение не переписывает.

### Другой Mac

Начиная с 3.20.0, после входа при первом запуске появляется предложение настройки сертификата, если ему ещё нет доверия. Нажми «Установить сертификат…» и подтверди действие. «Позже» откладывает настройку без повторного предложения при каждом запуске; кнопку всегда можно найти в настройках обновления. При уже доверенном сертификате предложение не появляется. Доверие автоматически не меняется.

В сборках с кнопкой установки открой **Настройки → Обновления → Установить сертификат…** и подтверди установку. Кнопка также находится в окне обновления. Приложение использует встроенный публичный сертификат с проверенным отпечатком и добавляет доверие только для подписи кода в пользовательскую связку «Вход». Пароль или подтверждение macOS вводятся в системном окне. После установки отображается зелёный статус; повторная установка не нужна.

Если старая версия приложения ещё не содержит эту кнопку, используй ручную установку ниже перед встроенным обновлением либо сначала установи новую версию вручную из DMG. Смена сертификата не отменяет отдельные требования Gatekeeper к первому запуску приложения.

Для запуска готовых сборок нужен только публичный `SSHHub-CodeSigning.cer`. Приватный ключ переносить не нужно. Проверь отпечаток:

```sh
openssl x509 -inform DER -in SSHHub-CodeSigning.cer -noout -fingerprint -sha256
```

Импортируй сертификат в связку «Вход» через «Связку ключей». В его свойствах раскрой «Доверие» и разреши только «Подпись кода», оставив остальные назначения по умолчанию. Эквивалентная явная команда из папки с сертификатом:

```sh
security add-trusted-cert -r trustRoot -p codeSign -k "$HOME/Library/Keychains/login.keychain-db" SSHHub-CodeSigning.cer
```

После установки сборки с этой подписью подтверди доступ к существующим паролям. Последующие обновления должны сохранять это разрешение. Сертификат не переносит сами пароли между Mac: некоторые секреты приложения хранятся с атрибутом `ThisDeviceOnly`.

Это локальная самоподписанная подпись, без Developer ID и нотарификации Apple. На другом Mac она не становится доверенной автоматически. Релизы, выпущенные до настройки сертификата, остаются ad-hoc; им нужна новая подписанная сборка.

### Сборка и сохранение ключа

`Scripts/build.sh` проверяет наличие действующей доверенной identity по публичному SHA-1 из `Signing/signing-identity.sha1` ещё до сборки. `Scripts/sign-app.sh` подписывает помощники, затем приложение, и проверяет их сертификаты и целостность. `Scripts/package-dmg.sh`, включая `--skip-build`, проверяет ту же подпись. При недоступном сертификате нет автоматического перехода на ad-hoc.

```sh
zsh Scripts/sign-app.sh --check
zsh Scripts/build.sh /private/tmp/ssh-hub-build
zsh Scripts/sign-app.sh --verify '/private/tmp/ssh-hub-build/SSH Hub.app'
python3 Tests/SigningContinuityTests.py
```

Последняя проверка использует два разных временных приложения и отдельную временную Связку ключей с синтетическим паролем. Проверяются чтение без диалога после пересборки, отказ для ad-hoc с тем же bundle ID, повреждённая сборка и отсутствие сертификата. Пользовательские пароли не читаются.

Для разработки без приватного ключа разрешён только явный выбор:

```sh
SSH_HUB_SIGN_IDENTITY=- zsh Scripts/build.sh /private/tmp/ssh-hub-dev
```

Такие сборки снова имеют меняющуюся ad-hoc идентичность; не подменяй ими постоянные релизы. Переопределение на другой сертификат допускается через `SSH_HUB_SIGN_IDENTITY` с его полным SHA-1 и означает смену идентичности.

Приватный ключ хранится в связке «Вход» на Mac сборки. Для резервной копии можно вручную экспортировать сертификат вместе с ключом из раздела «Мои сертификаты» в защищённый паролем PKCS#12 и сохранить вне репозитория. Для сборки на другом Mac нужен именно этот ключ и сертификат, а не новый сертификат с похожим именем. Утрата или замена ключа нарушит непрерывность подписи. Файлы `.p12`, `.pfx`, `.key` и `.keychain-db` исключены из Git.
