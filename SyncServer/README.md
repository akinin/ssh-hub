# Необязательная облачная синхронизация SSH Hub

Приложение работает локально без сервера и учётной записи. Для обмена между Mac можно подключить собственный сервер по HTTPS. Самостоятельной регистрации нет: первый администратор создаётся из консоли, остальных пользователей он добавляет через веб-панель. Каждый пользователь получает отдельное хранилище; администратор управляет доступом, но мастер-пароль расшифровки серверу не передаётся.

## Подключение приложения

1. В настройках открой «Хранилище и синхронизация». Создай мастер-пароль от 12 символов и выбери, переносить ли сохранённые пароли и MFA. Приложение запросит подтверждение владельца Mac и сохранит проверенную зашифрованную копию перед переключением. Исходные файлы и Связка ключей сохраняются.
2. Для локальной работы больше ничего не требуется. Для синхронизации укажи HTTPS-адрес, имя пользователя и пароль облачной учётной записи, выданные администратором.
3. Введи мастер-пароль в верхнем поле и нажми «Синхронизировать». Обмен выполняется по кнопке, при разблокированной базе и без активных сеансов/операций. Повторный снимок без изменений не создаётся.
4. На другом Mac создай локальную базу, войди в ту же облачную учётную запись и используй тот же мастер-пароль при обмене. Полученные записи сохраняются локально и доступны без сервера. Пути к приватным SSH-ключам и другим локальным файлам выбери на этом устройстве.

Пароль входа в облако и мастер-пароль шифрования имеют разное назначение. Сброс пароля учётной записи не расшифровывает базу и не восстанавливает забытый мастер-пароль. Мастер-пароль не сохраняется. Выход из облака/отключение синхронизации сохраняет локальные данные.

Передаются записи, профили/папки, оформление, избранное, документация с историей, команды, вложения, инвентаризация, пароли, MFA и общие учётные данные. Приватные SSH-ключи, VPN-секреты, внешние KeePass-базы и машинные пути остаются локальными. Обычный JSON-экспорт не получает MFA; зашифрованная копия SQLite содержит всё содержимое базы.

При одновременном изменении одного объекта на двух устройствах выбирается версия явно. Выбор привязан к просмотренному снимку: новые изменения потребуют повторного решения. Сервер принимает запись только с точной ожидаемой ревизией. Откат сервера ниже последней подтверждённой ревизии останавливает обмен.

## Развёртывание Debian 13

Используй отдельный непривилегированный LXC без nesting: 1 CPU, 1 ГБ RAM, 8 ГБ диска для небольшого числа пользователей. Сервер использует только Python 3 со стандартной библиотекой и SQLite; на Debian доступен `hashlib.scrypt`. Административная консоль Proxmox остаётся способом обслуживания.

Размести в `/opt/ssh-hub-sync` только `server.py`, `accounts.py`, `cloud.py`, `admin.py`, `index.html`, `backup.py`, `install.sh` и три systemd unit/timer файла. Исходники должны принадлежать root и быть недоступны сервису для записи. Запусти `sh /opt/ssh-hub-sync/install.sh` от root. Установщик не меняет SSH, DNS, маршрутизацию или NAT. `server.py` является библиотекой хранилища; `client.py` и `crypto.py` — прежний эталонный SSH-клиент для тестов, приложение использует HTTPS.

API слушает порт 8788. В unit-файле задай `SSH_HUB_SYNC_ORIGIN` (полный HTTPS origin) и `SSH_HUB_SYNC_PROXY` (адрес доверенного обратного прокси). В NPM настрой HTTPS-хост на HTTP-порт контейнера, действующий доверенный сертификат, принудительный HTTPS, `client_max_body_size 8m`, тайм-ауты 90 секунд и запрет кеширования. Для частной сети ограничь доступ LAN/VPN CIDR на прокси; не публикуй порт 8788 через NAT. Upstream принимает запросы только от заданного прокси с `X-Forwarded-Proto: https` либо loopback. Клиент использует штатную проверку TLS и не следует перенаправлениям.

Из root-консоли контейнера с TTY:

```sh
python3 -I /opt/ssh-hub-sync/admin.py create-admin ADMIN_USERNAME
```

Пароль вводится дважды скрыто. Не передавай его в аргументах, переменных окружения или чатах. Дальше войди на HTTPS-адресе сервера: администратору доступны список, создание и отключение обычных пользователей. Консоль поддерживает также `create-user`, `reset-password` и `list`. Отключение пользователя или сброс пароля отзывают все его сессии; повторное включение не возвращает старые токены.

## Доступ и хранение

Пароли аккаунтов хешируются scrypt (N=131072, r=8, p=1), случайная соль 16 байт. Случайные токены действуют 30 дней; в серверной БД сохраняются только SHA-256 токенов. Не более 20 сессий на аккаунт. Ограничены попытки входа, число потоков, размер тела запроса и срок ожидания. Browser-cookie — Secure/HttpOnly/SameSite=Strict; изменения из браузера требуют same-origin и CSRF. Общедоступного signup API нет.

`/var/lib/ssh-hub-sync/cloud/accounts.sqlite3` содержит учётные записи, роли и хеши сессий. Данные пользователей — отдельные SQLite в `cloud/users/<account UUID>/sync.sqlite3`, каталоги 0700, файлы 0600. UUID хранилища проверяется по вошедшей учётной записи; произвольный UUID из запроса не даёт доступ к другому пользователю. Лимит — 512 МиБ на пользователя и 2 ГиБ суммарно. Сохраняются до 20 ревизий; незавершённые блоки защищены 24-часовой арендой.

Шифрование снимков `SSHHUBS1`: PBKDF2-HMAC-SHA256 (600000), случайная соль 16 байт, AES-256-GCM, случайные nonce. Манифест аутентифицирует UUID хранилища, ревизию, UUID снимка, размеры и хеши; блоки по 4 МиБ связаны с UUID снимка и порядком. Сервер хранит шифротекст и не знает мастер-пароль. Размеры, время, имена облачных пользователей и число ревизий скрытыми не являются. Корректность шифрования проверяет клиент; сервер не расшифровывает снимки.

## Резервные копии

Таймер делает ежедневную online-копию account DB и каждой пользовательской SQLite через SQLite backup API с проверкой и атомарной заменой. Файлы находятся в `/var/backups/ssh-hub-sync/cloud/accounts/latest.sqlite3` и `cloud/users/<account UUID>/latest.sqlite3`. Между отдельными базами нет общей транзакции: для согласованного полного восстановления останови API и используй внешнюю резервную копию контейнера. Копия внутри того же LXC не защищает от потери хоста. Пароли входа хешированы, данные зашифрованы; сессии также входят в account DB, поэтому резервные копии должны оставаться приватными.

Для восстановления останови API, сохрани текущие базы отдельно, проверь целостность копий, восстанови их с владельцем `ssh-hub-sync` и правами 0600. Клиент обнаружит откат ревизии; не удаляй его baseline для обхода проверки. Процедура аварийного восстановления с принудительным выбором истории в интерфейсе пока не предусмотрена.

## Проверки

```sh
# Python с OpenSSL/scrypt и cryptography для эталонных crypto-тестов:
python3 -m unittest discover -s SyncServer -p 'test_*.py' -v
# Нативная база, миграция и merge на собственных временных данных:
swift test --filter PortableVaultTests
```

`CloudIntegrationTests` по умолчанию пропускается. Он требует явно переданный путь `SSH_HUB_CLOUD_TEST_FILE` к собственной временной учётной записи с префиксом `qa-`; файл и аккаунт удаляются после проверки. Тесты никогда не мигрируют пользовательскую Связку ключей. [Форматы и границы реализации](VAULT-DESIGN.md).
