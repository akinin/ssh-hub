# Переносимое хранилище и синхронизация

## Локальная база

`PortableVault.swift` реализует SQLite с двумя таблицами: заголовок формата 1 и зашифрованные объекты. Мастер-пароль через PBKDF2-HMAC-SHA256 (600000, salt 16 байт) оборачивает случайный 256-битный ключ AES-GCM. Этот ключ шифрует имена/значения объектов; индекс — HMAC-SHA256 имени. AAD связывает шифротекст с UUID базы и индексом. Не используются SQLCipher или платформенный формат Keychain, поэтому формат можно реализовать на Windows стандартными SQLite/PBKDF2/AES-GCM.

SQLite работает с synchronous FULL, DELETE journal, trusted_schema OFF; записи ограничены по размеру. Вложенные операции используют savepoint внутри общей транзакции. Файлы 0600 и каталоги 0700, ссылки/специальные файлы отвергаются. Шифрование не скрывает общий размер и число объектов. Локальная защита не распространяется на оставленные исходные SSH-конфиги или файлы старого формата.

`PortableSecretBridge` устанавливается только при существующей/явно созданной базе. Заблокированная, отсутствующая после активации или повреждённая база не переключается автоматически на старые секреты. Пароли и MFA читаются через прежние API с новым backend. Ключ расшифровки хранится в памяти, сбрасывается при блокировке приложения/сеанса macOS; временные расшифрованные вложения удаляются. Для подключения OpenSSH необходимы приватные transport config без паролей; пути и параметры подключения могут присутствовать в них на диске, как и в исходном SSH-конфиге.

## Миграция

Пользователь задаёт мастер-пароль, выбирает перенос паролей/MFA, подтверждает владельца Mac и выбирает новый файл зашифрованной копии. Во временную SQLite собираются записи, документы, команды, инвентаризация, вложения, файлы лицензий, общие учётные данные и оформление/профили. Объекты перечитываются и сравниваются, online-backup завершается до атомарного no-replace rename. Смена рабочей области или авторизации прерывает перенос. Исходные файлы и Keychain не удаляются.

Импортированные raw SSH-алиасы становятся локальными записями со стабильными UUID и ссылкой на исходный alias identity; исходный конфиг не переписывается. Локальное скрытие удалённого исходного алиаса сохраняется транзакционно, чтобы он не появлялся снова после reload. Внешний `ssh alias` продолжает читать исходный SSH-конфиг. Последующие изменения записи в базе сами по себе не обновляют этот внешний конфиг.

Сохранённый файл SQLite и мастер-пароль позволяют прочитать полную новую базу, включая MFA. Экспорт копии доступен в настройках. Интерфейс замены существующей базы из копии и удаления старых источников пока не добавлен; для возврата к прежнему хранению нужны сохранённые исходники и отдельное контролируемое отключение базы. Обычный JSON/legacy backup сохраняет прежние правила исключения секретов/MFA.

## Снимки и слияние

Снимок — канонический JSON `VaultCollection` формата 1: объект `profiles`, объекты `record/<UUID>` и `shared/<profile UUID>`. Запись содержит BackupRecord, пароль и необязательный TOTP; общие credentials содержат metadata и пароли без внешних KDBX. Локальные пути ключей/CA/serial/приложений и VPN refs нормализуются, при применении сохраняются значения текущего устройства. Связи туннелей и credentials передаются через стабильные UUID. Внешняя привязка KeePass передаётся только как признак необходимости локальной настройки; новый Mac блокирует fallback к паролю записи до явного выбора credentials. Прежняя локальная привязка KeePass сохраняется.

Сервер видит только зашифрованный `SSHHUBS1` пакет и блоки. Локальные `sync/base` и `sync/revision` входят в зашифрованную базу. Трёхстороннее слияние сравнивает значения объектов с общей базой; отсутствие — удаление. Изменения разных объектов объединяются; одновременное различное изменение одного объекта требует выбора пользователя. Выбор действует только для той же комбинации base/local/remote/revision. Объекты проходят typed validation и проверку ссылок до транзакционного применения. Ошибка сервера сохраняет локальные данные и старый baseline для безопасного повтора. CAS-конфликт не обходится новым head ради безусловного overwrite.

## Облачная учётная запись

Пароль входа отправляется только по HTTPS для авторизации и не используется как мастер-пароль. Сессионный токен хранится внутри зашифрованной локальной базы, привязан к HTTPS origin и UUID хранилища. Смена сервера/пользователя поверх подтверждённой истории запрещена, чтобы не отправить данные другой учётной записи. Выход удаляет локальный токен и пытается отозвать серверную сессию; при offline локальный выход всё равно работает. Уже выданный токен на недоступном сервере живёт до срока/отзыва администратором.

Обмен ручной. Новый Mac сначала создаёт локальную базу, затем входит в облако и получает снимок с общим мастер-паролем. Автоматический фоновый обмен, общий доступ между разными пользователями, восстановление забытого мастер-пароля и согласованная ротация мастер-пароля всех устройств не реализованы. Не добавляй сохранение мастер-пароля в preferences/argv/env ради автоматизации.
