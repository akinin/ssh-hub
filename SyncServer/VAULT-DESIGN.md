# Переносимое хранилище и синхронизация

## Локальная база

`PortableVault.swift` реализует SQLite с двумя таблицами: заголовок формата 1 и зашифрованные объекты. Мастер-пароль через PBKDF2-HMAC-SHA256 (600000, salt 16 байт) оборачивает случайный 256-битный ключ AES-GCM. Этот ключ шифрует имена/значения объектов; индекс — HMAC-SHA256 имени. AAD связывает шифротекст с UUID базы и индексом. Не используются SQLCipher или платформенный формат Keychain, поэтому формат можно реализовать на Windows стандартными SQLite/PBKDF2/AES-GCM.

SQLite работает с synchronous FULL, DELETE journal, trusted_schema OFF; записи ограничены по размеру. Вложенные операции используют savepoint внутри общей транзакции. Файлы 0600 и каталоги 0700, ссылки/специальные файлы отвергаются. Шифрование не скрывает общий размер и число объектов. Локальная защита не распространяется на оставленные исходные SSH-конфиги или файлы старого формата.

`PortableSecretBridge` устанавливается при запуске, включая состояние без выбранной базы. Заблокированная, отсутствующая после активации или повреждённая база не переключается автоматически на старые секреты. Пароли и MFA читаются через прежние API с новым backend. Ключ расшифровки хранится в памяти, сбрасывается при блокировке приложения/сеанса macOS; временные расшифрованные вложения удаляются. Для подключения OpenSSH необходимы приватные transport config без паролей; пути и параметры подключения могут присутствовать в них на диске, как и в исходном SSH-конфиге.

База обязательна: HubSession создаёт рабочую область только после расшифрования всех объектов и обновления формата. Без базы доступны выбор файла, создание и явный импорт. При закрытии базы рабочая область удаляется и операции завершаются до открытия следующей. Все постоянные данные приложения хранятся внутри базы; KeePass-файл остаётся внешним.

Touch ID получает корневой ключ из отдельного несинхронизируемого элемента Keychain с доступом WhenUnlockedThisDeviceOnly и biometryCurrentSet. Account связан с UUID и fingerprint заголовка базы. Мастер-пароль не сохраняется. На другом Mac нужны мастер-пароль и новое включение Touch ID. Отменённый или устаревший callback не может разблокировать другой файл.

Для OpenSSH/curl/открытия вложений используются временные копии 0600 в отдельном каталоге 0700. Материализация сериализована с блокировкой базы; каталог удаляется при блокировке/штатном выходе. Flock защищает активные каталоги других экземпляров; после аварийного выхода оставшийся каталог нового формата удаляется при следующем запуске. Это не гарантированное физическое стирание данных с SSD; включённый FileVault обеспечивает защиту диска вне работающего сеанса.

## Миграция

Пользователь задаёт мастер-пароль, выбирает перенос паролей/MFA, подтверждает владельца Mac и выбирает новый файл зашифрованной копии. Во временную SQLite собираются записи, документы, команды, инвентаризация, вложения, файлы лицензий, общие учётные данные и оформление/профили. Объекты перечитываются и сравниваются, online-backup завершается до атомарного no-replace rename. Смена рабочей области или авторизации прерывает перенос. Исходные файлы и Keychain не удаляются.

Импортированные raw SSH-алиасы становятся локальными записями со стабильными UUID и ссылкой на исходный alias identity; исходный конфиг не переписывается. Локальное скрытие удалённого исходного алиаса сохраняется транзакционно, чтобы он не появлялся снова после reload. Внешний `ssh alias` продолжает читать исходный SSH-конфиг. Последующие изменения записи в базе сами по себе не обновляют этот внешний конфиг.

Сохранённый файл SQLite и мастер-пароль позволяют прочитать полную новую базу, включая MFA. Экспорт копии доступен в настройках. Файл копии можно выбрать в стартовом окне базы. Старые источники не удаляются автоматически. Обычный JSON/legacy backup сохраняет прежние правила исключения секретов/MFA.

## Снимки и слияние

Снимок — канонический JSON `VaultCollection` формата 2: объект `profiles`, объекты `record/<UUID>`, `shared/<profile UUID>` и необязательный `builtin`. Формат 1 остаётся доступен для чтения. Запись содержит BackupRecord, пароль и необязательный TOTP; общие credentials содержат metadata и пароли без внешних KDBX. Встроенные SSH-ключи, CA и VPN/API-секреты передаются внутри `builtin` вместе с настройками и материалами интеграций. Ссылки ключей содержат идентификаторы объектов базы. `builtin` — одна единица явного разрешения конфликта; она включает логическое пространство имён исходной базы, чтобы привязки на другом Mac читались без прежних файлов. Пути serial/приложений остаются параметрами текущего устройства; размещение окон и активные сеансы не передаются. Связи туннелей и credentials передаются через стабильные UUID. Внешняя привязка KeePass передаётся только как признак необходимости локальной настройки; новый Mac блокирует fallback к паролю записи до явного выбора credentials. Прежняя локальная привязка KeePass сохраняется.

Сервер видит только зашифрованный `SSHHUBS1` пакет и блоки. Локальные `sync/base` и `sync/revision` входят в зашифрованную базу. Трёхстороннее слияние сравнивает значения объектов с общей базой; отсутствие — удаление. Изменения разных объектов объединяются; одновременное различное изменение одного объекта требует выбора пользователя. Выбор действует только для той же комбинации base/local/remote/revision. Объекты проходят typed validation и проверку ссылок до транзакционного применения. Ошибка сервера сохраняет локальные данные и старый baseline для безопасного повтора. CAS-конфликт не обходится новым head ради безусловного overwrite.

## Облачная учётная запись

Пароль входа отправляется только по HTTPS для авторизации и не используется как мастер-пароль. Сессионный токен хранится внутри зашифрованной локальной базы, привязан к HTTPS origin и UUID хранилища. Смена сервера/пользователя поверх подтверждённой истории запрещена, чтобы не отправить данные другой учётной записи. Выход удаляет локальный токен и пытается отозвать серверную сессию; при offline локальный выход всё равно работает. Уже выданный токен на недоступном сервере живёт до срока/отзыва администратором.

Обмен ручной. При первом обмене клиент проверяет пароль шифрования по существующему снимку или публикует первый снимок. Производный ключ и соль сохраняются в объекте `sync/key` зашифрованной локальной базы с привязкой к HTTPS-адресу и UUID облачного хранилища. Ключ исключён из облачного снимка. Клиенты сохраняют соль при последующих записях, каждый манифест и блок используют свежий AES-GCM nonce. Старый клиент может опубликовать снимок с новой солью. Тогда новый клиент запросит пароль и заменит ключ только после проверки снимка.
