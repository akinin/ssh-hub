# MCP для ИИ-агентов

SSH Hub предоставляет локальный MCP-сервер через Streamable HTTP. Агент может находить записи текущего профиля, читать и редактировать документацию и инвентаризацию, создавать записи, выполнять SSH-команды и запускать штатный сбор инвентаризации.

## Подключение

1. Открой и разблокируй базу SSH Hub.
2. В **Настройки → MCP** включи подключение ИИ-агентов.
3. Нажми **Копировать конфигурацию MCP** и добавь конфигурацию в свой MCP-клиент. Нужен клиент с поддержкой Streamable HTTP и заголовка Authorization.
4. При необходимости включи разрешения на создание записей, изменение документации, инвентаризации и выполнение SSH-команд. После изменения разрешений переподключи клиент, чтобы он обновил список инструментов.

Пример структуры конфигурации (настоящий ключ копируется в настройках):

```json
{
  "mcpServers": {
    "ssh-hub": {
      "url": "http://127.0.0.1:22722/mcp",
      "headers": {"Authorization": "Bearer <ключ из SSH Hub>"}
    }
  }
}
```

Ключ даёт доступ к материалам открытой базы. Передавай его только доверенному клиенту. Кнопка **Сменить ключ** отзывает прежний ключ и отменяет запросы. Настройки и ключ хранятся в зашифрованной базе отдельно для этого Mac и пользователя macOS; облачная синхронизация их не переносит.

Сервер по умолчанию выключен, слушает только `127.0.0.1`, не публикуется в локальной сети и не требует облачной учётной записи. Порт можно изменить. В случае конфликта порта приложение показывает ошибку и не занимает другой адрес автоматически. HTTP здесь используется только для локального соединения на одном Mac.

## Инструменты

| Инструмент | Назначение |
| --- | --- |
| `workspace_status` | Активный профиль, число записей и разрешения. |
| `records_list` | Поиск и постраничный список записей; до 100 записей за запрос. |
| `records_get` | Название, тип, адрес, пользователь, порт и группа записи. |
| `documentation_get` | Текущий текст документации и ревизия для безопасного изменения. |
| `inventory_get` | Поля инвентаризации, последний собранный снимок и допустимые ключи полей. |
| `records_create` | Запрос на создание записи без паролей и изменения SSH-конфига. |
| `documentation_write` | Запрос на дополнение или замену документации. |
| `inventory_write` | Запрос на изменение выбранных полей инвентаризации. |
| `ssh_run` | Запрос одной SSH-команды на сохранённой SSH-записи. |
| `inventory_collect` | Запрос сбора Linux, RouterOS или macOS через SSH. |
| `jobs_get` | Статус запроса и результат выполнения. |
| `jobs_cancel` | Отмена ожидающего или выполняемого запроса. |

Инструменты изменения и выполнения видны только при включённом соответствующем разрешении. Обязательные и допустимые аргументы клиент получает через `tools/list`.

Сначала агент вызывает `workspace_status`, затем передаёт полученный `profile_id` в инструменты записей и материалов. `record_id` — непрозрачный идентификатор из `records_list`. Запрос другого профиля отклоняется; просмотр всех профилей через MCP не предоставляется.

## Подтверждение действий

Каждое изменение и каждый запуск возвращают `job_id` со статусом `pending_approval`. В SSH Hub открывается отдельное окно с назначением и точным содержимым запроса. Только пользователь может нажать **Разрешить**. Закрытие окна отклоняет запрос; без ответа он истекает через 2 минуты. Агент не получает инструмента подтверждения.

После подтверждения агент опрашивает `jobs_get`, например раз в секунду. Возможные статусы: `pending_approval`, `running`, `completed`, `failed`, `cancelled`, `rejected`, `expired`. У завершённого запроса есть поле `result`. Результаты остаются в памяти, пока открыта рабочая область; это не постоянная история команд.

SSH-команды проходят существующий `MaintenancePlan`: проверку назначения и конфигурации, штатную авторизацию SSH, проверку ключа сервера, маршрутизацию и ограничение времени (1–120 секунд). Запрос не вводит команды в открытый терминал и не запускает локальную оболочку. Вывод ограничен 64 К символов; ошибки подключения и отмена не считаются успешным выполнением.

При записи документации и инвентаризации нужен `expected_revision` из соответствующего инструмента чтения. Если данные изменились после запроса, операция отклоняется. Предыдущая документация и несохранённый черновик сохраняются в истории. Изменение инвентаризации при существующем черновике отклоняется; собранные снимки и поля, не указанные в запросе, сохраняются. Сбор создаёт снимок и не заменяет ручные значения автоматически.

## Границы доступа

- MCP доступен только при разблокированной базе. Он не может выбрать или разблокировать базу.
- Блокировка останавливает сервер и операции, закрывает подтверждение, удаляет запросы и результаты. Смена профиля также отменяет запросы и очищает результаты.
- Пароли, секреты MFA, приватные ключи, произвольные объекты базы и исходные SSH-опции не выдаются. URL записей возвращаются без userinfo, query и fragment. Сам текст документации или вывода может содержать информацию, которую пользователь туда поместил: разрешение чтения следует давать осознанно.
- Вызовы из браузерной страницы с заголовком Origin отклоняются; CORS и cookies не используются. Для каждого запроса проверяются Host и Bearer-ключ.
- Ограничены размер HTTP-запроса, число соединений, частота запросов, очередь подтверждений и объём результатов. В журнал не записываются ключ доступа, тела запросов и вывод команд.
- Приложение поддерживает протоколы `2025-03-26`, `2025-06-18`, `2025-11-25` с initialize и `2026-07-28` с server/discover. Транспорт без состояния, JSON-ответы на POST; SSE, HTTP-сессии, stdio, OAuth и удалённое подключение не предоставляются.

## Проверка разработчиком

`Tests/Vault/MCPTests.swift` использует собственные временные базы, синтетические секреты и внедрённый исполнитель SSH. Проверяет HTTP на loopback, авторизацию, версии протокола, изоляцию профиля, подтверждение, CAS, отмену, блокировку и отсутствие секретов в выдаче. Реальные серверы, пользовательские ключи и базы в QA не используются.
