# Уведомления об SSH-сессиях в Telegram

Серверная часть для явной установки и управления из SSH Hub. Требуются Linux,
Python 3.9+, systemd, `pam_exec.so`, SSH-вход root и уже включённый `UsePAM`
с PAM-сервисом `sshd`. Пакеты, межсетевой экран, способы входа и конфигурация
sshd не меняются. Установка показывает план и требует отдельного запуска.

Это уведомления об открытии PAM-сессии после аутентификации. Они могут включать
SSH-команды и SFTP, а не только интерактивную консоль. Неудачные попытки входа
не отслеживаются. Другие PAM-сервисы, Proxmox webhook и `/etc/pve` не затрагиваются.

## Как работает доставка

В `/etc/pam.d/sshd` добавляется одна строка:

```text
session [default=ignore] pam_exec.so quiet quiet_log type=open_session /usr/bin/python3 -I /usr/local/lib/ssh-hub-login-notify/notify.py --enqueue
```

Она игнорирует результат помощника. Помощник не выполняет DNS, HTTP, командную
оболочку или запись в дисковую очередь. Он передаёт ограниченное событие через
неблокирующий UNIX datagram socket и всегда возвращает 0. Если службы нет или
локальный буфер заполнен, событие пропускается: вход не ждёт Telegram.

`ssh-hub-login-notify.service` работает независимо от Mac. Служба принимает только
сообщения локального UID 0 и сохраняет принятые события в закрытую очередь:
до 128 событий, до трёх попыток и не дольше часа. Для каждого отправления
создаётся один дочерний процесс с общим пределом 8 секунд, включая DNS.
Сервер использует только проверяемый HTTPS `api.telegram.org`, JSON без
`parse_mode`, без proxy и переходов по редиректам. Ответ ограничен 64 КиБ.
Отправления разделены минимум 3,1 секунды; `retry_after` ограничивает всю
очередь текущего чата. Доставка является best effort: пропуски при переполнении
и повтор при неоднозначной сетевой ошибке возможны.

## Пути и секреты

- `/usr/local/lib/ssh-hub-login-notify/notify.py`: root, 0755.
- `/etc/ssh-hub-login-notify/config.json`: root, 0600; каталог 0700.
- `/var/lib/ssh-hub-login-notify/`: root, 0700; `manifest.json`, `status.json`
  и файлы `queue/<32hex>.json` имеют 0600.
- `/etc/systemd/system/ssh-hub-login-notify.service`: root, 0644.
- `/run/ssh-hub-login-notify/`: временный каталог systemd, root 0700;
  `events.sock` имеет 0600.
- `/var/lib/ssh-hub-login-notify.lock`: root, 0600, блокировка управления.

Токен вводится в защищённое поле приложения и передаётся по SSH только через
stdin. На сервере он хранится только в закрытой конфигурации; во время отката
возможна временная закрытая копия в транзакции. Токен не попадает в argv,
переменные окружения, журнал, ответ управления или общедоступные материалы.
Состояние доставки содержит только фиксированное значение и UTC-время.

## Управление и совместимость

`manage.py` исполняется как просмотренный Python-код и принимает ограниченный
JSON через stdin. Доступны `inspect`, `install`, `configure`, `enable`, `disable`,
`remove`. `inspect` ничего не создаёт и не изменяет. Каждая мутация требует
`expected_revision` от свежей проверки; конкурентное изменение, ссылка,
небезопасный владелец/права или неизвестная установка блокируют операцию.

Отключение сохраняет настройки и токен, выключает службу и оставляет быстрый
неактивный PAM-хук. Удаление убирает только распознанные файлы и хук. Посторонние
файлы остаются с предупреждением; непустые чужие каталоги нельзя использовать
для новой установки.

Прежняя настройка `/usr/local/sbin/ssh-login-telegram` распознаётся только при
совпадении известного SHA-256, точной строки PAM и закрытого простого конфига
с четырьмя ожидаемыми полями. Содержимое конфига никогда не выполняется как shell.
Управление ею требует явного `install` с `adopt_legacy=true`. Пустой токен
сохраняет прежний серверный токен; он не выгружается на Mac. Неизвестные варианты
автоматически не принимаются и не удаляются.

Перед изменениями создаются закрытые снимки для отката в
`/var/lib/.ssh-hub-login-transaction-*`. После успеха или успешного отката они
удаляются. Если операция была жёстко прервана или откат не завершился, каталог
с `transaction.json` и пронумерованными снимками остаётся для администратора.
Проверка показывает его путь и блокирует новые мутации кодом `recovery_required`.
Метаданные снимков указывают исходный путь, права, владельца и группу.
SSH Hub не заменяет данные, которые администратор изменил уже после начала
операции, и не запускает автоматическое восстановление после потери связи.

Для личного чата сначала нужно открыть бота и отправить ему сообщение.
При использовании группы/канала бот должен иметь право отправки сообщений.
SSH Hub не вызывает `getUpdates` и не меняет webhook существующего бота.

## Проверки

```sh
PYTHONDONTWRITEBYTECODE=1 python3 LoginNotifications/test_manage.py
PYTHONDONTWRITEBYTECODE=1 python3 LoginNotifications/test_notify.py
```

Проверки используют только временные каталоги, фиктивный systemctl и подменённые
HTTP/UNIX-транспорты. Они не подключаются к Telegram, пользовательским серверам
или настоящему PAM. Работа настоящего Linux `SO_PASSCRED`, systemd и PAM требует
отдельной проверки на разрешённом тестовом сервере; macOS-тесты её не заменяют.
